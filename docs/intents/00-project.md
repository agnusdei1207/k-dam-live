# 프로젝트 인텐트 · K-DAM LIVE

- 작성 2026-09-15

## 왜

한국의 댐 저수율·수위·유입·방류량은 K-water 물정보포털에 공개되어 있지만, 여러 화면을 오가야 하고 모바일에서 읽기 어렵다. K-DAM LIVE는 그 관측 자료를 한 화면의 고밀도 표와 상세 모달로 보여 주는 정적 사이트다. 사이트가 보여 주는 숫자는 예외 없이 포털의 실제 관측값이어야 한다. 그렇지 않은 숫자는 결함이다.

## 제약

- 순수 정적 사이트. 런타임 프레임워크·번들러·서버 없이 GitHub Pages 에서 서빙한다. 데이터는 배포 시점에 생성한 JSON 파일이다.
- 데이터 출처는 K-water 물정보포털(MyWater) 댐/보 수문자료 AJAX 엔드포인트 하나다. 인증키가 없고 CORS 가 막혀 있으므로 GitHub Actions 가 수집한다. 계약은 `docs/data-pipeline.md` 가 소유한다.
- 화면의 어떤 수치도 하드코딩·난수·합성 추이로 만들지 않는다. 포털에 값이 없으면 `-` 로 표시한다.
- 댐 목록은 포털이 관측 자료를 제공하는 K-water 관할 댐(36개)으로 한정한다. 다른 기관 댐은 자료가 생길 때 추가한다.
- 수집 실패 시 직전 배포본을 유지한다. 빈 데이터 배포는 금지다.
- 색·간격·모션 토큰은 `css/tokens.css` 를 따르고, 표는 데스크톱(1024px 이상)에서 가로 스크롤 없이 9열이 들어가야 한다.
- 포털이 발표하지 않는 판정(가뭄 단계, 홍수 주의, 방류 상태)을 사이트가 만들어 붙이지 않는다. 비교는 포털의 예년 저수율로 하고, 저수율 색 구간은 시각 단계일 뿐이다.
- 커밋 메시지는 `feat:`/`fix:`/`refactor:`/`docs:`/`ci:` 접두어, AI 도구명·공동 작성자 트레일러 금지(`AGENTS.md`).

## 영구 결정

- 2026-09-15: 데이터 파일을 저장소에 커밋하지 않고 배포 시점에 생성한다. 이유: 매시간 커밋이 이력을 오염시키고, 정적 산출물은 Pages 아티팩트에 실으면 충분하다.
- 2026-09-15: 동복댐(광주시 관할)·가화댐은 공개 관측 피드가 없어 목록에서 제외했다. 포털이 제공하는 안계·대곡·연초·구천댐을 대신 포함했다.
- 2026-09-15: 홍수조절댐(평화의댐)은 평시에 비워 두므로 전국·수계 평균과 예년 비교에서 제외한다.
- 2026-10-26: 고정 기준(저수율 40·50·60%, 방류량 20㎥/s, 수위 비율)으로 붙이던 상태 배지(가뭄경계·주의·관심, 방류 중, 홍수주의)를 없앴다. 이유: 공식 가뭄 단계는 댐마다 기준이 달라 고정 % 판정은 공식 용어를 빌린 추정이었고, 평상시 발전 방류까지 "방류 중"으로 보여 저수율이 낮은 댐의 상태를 가렸다. (사용자 지시: 틀리거나 하드코딩된 것은 보이지 않게 제거)
