# INTENT-0001 · 시뮬레이션 제거와 K-water 실측 자료 연결

- 상태: 완료
- 작성 2026-09-15 / 갱신 2026-09-15

## 왜

v1.x 사이트는 `js/data.js` 에 36개 댐의 저수율·수위·유입·방류량을 고정값으로 박아 두고, 3.2초마다 무작위로 1~2개 댐의 숫자를 흔들어 실시간처럼 보이게 했다. 주암댐을 비롯한 대부분 댐의 값은 실제와 무관했고, 추이 차트는 사인 함수로 그린 합성 곡선이었다. 사용자가 이를 발견했다. 사이트의 존재 이유가 실측 자료이므로 시뮬레이션은 전부 제거하고 공개 관측 자료로 대체해야 한다.

## 무엇

- 표·요약 카드·티커·모달·CSV 의 모든 수치가 K-water 물정보포털의 관측값이다.
- 헤더의 시각은 포털의 관측 시각(KST)이다.
- 상세 모달의 24시간·30일·1년·3년·5년 추이는 실측 시계열이다.
- 댐 제원(홍수위·만수위·저수용량·높이·길이 등)도 포털 제원을 쓴다.
- 포털에 값이 없으면 `-` 로 보이고, 수집이 실패하면 직전 배포본이 유지된다.

## 수용 기준

- [x] `npm run fetch` 가 36/36 댐의 현재 저수율을 채운 `data/live.json` 과 1825일 일별 저수율이 모두 채워진 `data/history.json` 을 생성한다.
- [x] 주암댐 현재 저수율이 포털 다목적댐 관리현황의 값과 일치한다 (2026-09-15 18시 기준 47.1%).
- [x] 코드 어디에도 `Math.random`, 고정 관측값(`baseRate` 등), 합성 추이 생성이 남아 있지 않다.
- [x] 브라우저(헤드리스)에서 36행이 렌더되고 필터·정렬·검색·모달 기간 전환·언어 전환·GPS 정렬·CSV 가 오류 없이 동작한다.
- [x] 배포 워크플로가 매시간 수집 후 배포하며, 수집 실패 시 배포 단계에 도달하지 않는다.
- [x] 문서(README·AGENTS·docs)와 메타(manifest·OG 이미지·JSON-LD)에 34개·15분 주기 같은 낡은 문구가 없다.
