# INTENT-0002 · 수치가 고정돼 보이는 문제 해결과 전수 점검·리팩터링

- 상태: 진행 중
- 작성 2026-10-26 / 갱신 2026-10-26

## 왜

사용자가 "수치가 항상 고정이고 주암댐도 그대로"라고 보고했다. 실측해 보니 자료는 진짜였다. 배포본과 포털을 직접 대조하니 36개 댐 모두 일치했고, 주암댐은 이틀 동안 41.4%에서 42.9%로 올랐다. 문제는 갱신 주기였다. 배포는 GitHub Actions의 매시 cron에 묶여 있었는데, GitHub이 이 cron을 3~5시간 간격으로만 실행했다(10/25 01:14, 06:09, 11:33, 16:24, 19:38, 22:34 UTC). 저수율은 시간당 0.0~0.1%p만 움직이므로, 화면은 몇 시간씩 같은 숫자를 보여 줬다.

사용자는 이어서 코드가 의도대로 동작하는지 전수 점검하고, 리팩터링을 강하게 하라고 요청했다. 앞으로의 작업이 [dev-skill](https://github.com/agnusdei1207/dev-skill) 방법론을 따르도록 강제하고 의도를 남기라는 요청도 했다.

## 무엇

- 포털이 새 시간 자료를 올리면 사이트가 대략 한 관측 시간 안에 그 값을 보여 준다.
- 화면의 모든 기능이 의도대로 동작하고, 그 사실을 다시 확인할 수 있는 검사가 저장소에 있다.
- 같은 규칙을 두 곳 이상에서 정의하는 코드, 죽은 코드, 오해를 부르는 이름이 없다.
- 이후 작업자(사람·AI)는 dev-skill 방법론과 이 저장소의 인텐트 문서를 따라야 한다.

## 수용 기준

### 배포 확인

- 0d34fee push (run 40283341829): validate가 실패했다. CI의 Node 20은 `node --test` 의 glob 인자를 펼치지 않아 `Could not find 'tests/*.test.mjs'` 로 끝났고, 배포 단계는 건너뛰어졌다.
- 같은 push에 GitHub Pages의 브랜치 빌드(run 40283340986, `pages build and deployment`)가 성공했다. 그 결과 데이터가 없는 저장소 원본이 배포되어, 약 3분 동안 `data/live.json` 이 404였다. Pages 설정이 `build_type: legacy`(main `/`)라서 push마다 이 빌드가 먼저 돌고, 평소에는 워크플로 배포가 뒤이어 덮어써 가려져 있었다.
- a0421de에서 테스트 파일을 명시적으로 나열했다. `npx node@20 --test …` 결과 16건 통과. run 40283642763 성공 후 배포본은 `generatedAt 2026-10-26T07:06:06Z · observedAt 2026-10-26 16:00 · 36 dams` 이고, 주암댐은 `98.383 m · 42.9 %` 로 포털 16시 자료를 반영했다.
- 남은 확인: 새 워크플로의 첫 예약 실행에서 게이트가 `false`(건너뜀)와 `true`(재수집)를 모두 내는지 확인해야 한다.

### 구조 지도 변경

`scripts/mywater.mjs`(포털 클라이언트 정본)와 `scripts/needs-update.mjs`(신선도 게이트)가 추가됐고, `tests/` 를 신설했다. `docs/ARCHITECTURE.md` 를 참조한다.

### 남는 위험

- 포털의 관리현황(getVers)은 시간별 수문자료(getHydr)보다 먼저 다음 시각으로 넘어간다. 2026-10-26 16시대에 getVers는 16시, getHydr는 15:00까지였다. 그 사이에는 게이트가 10분마다 재수집한다. 시간별 자료가 올라오면 멈춘다. 한 시간 늦게 반영되는 쪽보다 몇 번의 재수집 비용이 싸서 이 방식을 택했다.
- GitHub의 예약 실행 지연은 여전히 통제할 수 없다. 10분 간격은 실행 기회를 늘릴 뿐이다.
- Pages 원본이 `legacy`(브랜치)인 동안에는 push마다 데이터 없는 사이트가 잠깐 배포되고, 워크플로가 실패하면 그 상태로 남는다. 저장소 설정에서 Pages 원본을 "GitHub Actions"로 바꾸면 이 경쟁이 사라진다. 저장소 설정 변경이라 사람의 결정으로 남긴다(아래 질문).
- CI 런타임 Node 20은 2026-04 지원이 끝났다.
